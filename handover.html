Admin Handover

Seva Sponsorship App

This document hands over the Seva Sponsorship data-entry system — what it is, how the pieces fit together, and how to run it day to day. Everything here is a plain static website; there is no server to maintain beyond the two Google Apps Script endpoints, which already existed before this app and are shared with other applications.

1. Overview

Sponsors fill in a mobile-friendly form (index.html) to book a Seva date, naming themselves, an optional co-sponsor, and up to two ancestors ("Pitru") being honoured. On submit, the entry is written to a shared Google Sheet, a WhatsApp confirmation opens automatically, and the app switches to a searchable list of all entries. A separate page (report.html) exports all entries as a print-ready PDF, sorted by Seva date, for handing to the hoarding printer — including correct rendering of Telugu names. A third page (admin.html) lets you change the year, dates, and entry-window settings without touching any code.

The whole thing is plain HTML/CSS/JS hosted on GitHub Pages — no build step, no server, no database beyond the Google Sheet. To make a change, you edit a file (or generate one via admin.html) and push it to the GitHub repository; the live site updates automatically.

Do not reorder or rename the sheet's columns without also updating sheetHeaders in parameters.js to match. The write script matches fields to columns by header name, but the app reads rows back purely by column position — if the sheet's column order and sheetHeaders ever disagree, entries will display under the wrong labels in View Entries and the PDF report.

Duplicate entries (same sponsor mobile submitting more than once) are allowed by design.

4. How the entry window works (minGapDays)

There are no fixed "slots" — just one number, minGapDays, in parameters.js. A Seva date can be picked only while there are at least that many days between today and that date, and it must fall within the overall Seva period (sevaStartDate to sevaEndDate).

  • The earliest pickable date is always today + minGapDays (never earlier than sevaStartDate).
  • The latest pickable date is always sevaEndDate.
  • Entry closes automatically, with no action needed, once even the very last Seva date no longer has enough lead time.
  • Entry reopens automatically the moment you lower minGapDays and redeploy — there is no separate "reopen" switch.

Worked example — Seva period 01/10/2026–15/10/2026: with minGapDays = 5, entry closes automatically after 10/10/2026. If you then lower it to minGapDays = 2 (say, on 12/10/2026, to let in latecomers), entry reopens immediately and stays open through 13/10/2026.

All of this is evaluated in India Standard Time regardless of where in the world the page is opened from — a sponsor entering from abroad sees the same open/closed status as one entering from India.

There is also a separate master switch, dataEntryOpen (true/false), that overrides everything above — set it to false to force the form closed no matter what the dates say.

5. Day-to-day admin tasks

To change the year, dates, WhatsApp number, minGapDays, or script/sheet settings:

  1. Open admin.html in a browser (it prefills every field from the currently live parameters.js).
  2. Edit whatever needs changing. The live preview under Minimum Gap Days shows the exact last day entry will stay open.
  3. Click Generate parameters.js, review the code shown, then click Download parameters.js.
  4. Replace the existing parameters.js in the GitHub repository with the downloaded file, and commit/push (or upload via the GitHub web UI).
  5. The live site picks up the change as soon as GitHub Pages serves the new file — occasionally there is a short delay (a few minutes) due to caching; a hard-refresh on the live page clears it immediately.

To check current entries: open index.html → View Entries tab. Search by mobile number or sponsor name; tap any entry to see full details (gotras, co-sponsor, etc.).

6. Generating the hoarding PDF

  1. Open report.html. It loads all entries, sorted by Seva date, and shows a preview table on screen.
  2. Click Download PDF.
  3. Hand the downloaded PDF to the printer. Telugu names are embedded as sharp images so they display correctly (see §8) — no special software is needed to open or print it, any PDF viewer works.

7. WhatsApp confirmation

On a successful submission, the app automatically opens a WhatsApp chat (via a wa.me link) to the configured number with a prefilled confirmation message, then switches to the (freshly refreshed) View Entries tab so the new entry is visible immediately. This requires WhatsApp to be installed (on mobile) or WhatsApp Web to be logged in (on desktop).

Some browsers occasionally block this automatic popup (most often on a slow connection). As a fallback, the confirmation report shown right after submitting also includes its own "Send via WhatsApp" button that can be tapped manually.

8. Known quirks & caveats

  • Google Sheets sometimes reformats dates. Occasionally Sheets auto-converts the incoming date text into a real date-type cell; when read back, it can arrive as a raw timestamp instead of plain text. The app detects this automatically and converts it back to DD/MM/YYYY — you should never see a raw timestamp on screen or in the PDF. If you ever do, it's worth a quick check that this logic still matches how the sheet is behaving.
  • Telugu in the PDF is drawn as images, not text. The PDF library used (jsPDF) cannot correctly shape Telugu conjuncts and vowel signs on its own, so any Telugu name is rendered through the browser's own text engine onto a small canvas first, then dropped into the PDF as a crisp image. English and date cells remain normal, selectable PDF text. This means Telugu names in the PDF can't be copy-pasted as text, but they will display and print correctly.
  • All dates are Indian format, DD/MM/YYYY, everywhere in the app, and all "is entry open right now" checks use India Standard Time regardless of the visitor's own timezone.
  • Mobile numbers are validated as 10 digits starting with 6, 7, 8, or 9.
